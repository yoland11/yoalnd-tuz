# تبسيط النقل وحسابات المركبة والشراكة

الحالة: اعتمد صاحب المشروع النطاق والتصميم بطلب «كمل» بتاريخ 2026-11-03؛ اكتمل التنفيذ والفحص محلياً دون رفع أو نشر؛ راجع تقرير 2026-11-03.

## المطلوب

اختار صاحب المشروع تبسيط واجهة النقل وخطواته، وكذلك حسابات النقل وشراكة المركبة (الخياران 1 و3). هذا تغيير في عرض النظام الحالي وتسلسل استخدامه. لا يتضمن إعادة تصميم وصل الطباعة، ولا تغيير معادلات الحساب أو إنشاء نظام نقل آخر.

## الموجود الذي جرى فحصه

- `src/components/booking-transport-plan-editor.tsx`: رحلات النقل داخل الحجز، السائق والمركبة، الأجرة الكلية أو المستقلة، ملاحظات الوصل وفترة إشغال المورد. تغيير طريقة الأجرة له تأكيد قائم؛ الحفظ يفحص التعارضات عبر المسار الحالي.
- `src/views/admin/vehicles.tsx`: قائمة المركبات وتفاصيلها، الرحلات والمصاريف والصيانة، والتنبيه إلى الحجوزات غير المرتبطة بمركبة.
- `src/views/admin/vehicle-partnership.tsx`: اتفاق الشراكة، النشاط، الإغلاق الشهري، المستحقات، طلبات الصرف والتقارير. طلب الصرف يحتفظ بنسخة المصدر ومفتاح المحاولة؛ الدفع يخضع للموافقة المركزية.
- `src/views/admin/vehicle-partnership-history.tsx` و`vehicle-partnership-costs.tsx` و`vehicle-partnership-reports.tsx`: التفاصيل التاريخية والتكاليف والتقارير المرتبطة بالميزة الحالية.
- `src/views/admin/enterprise.tsx`: تبويب أرباح السيارات الحالي في غرفة العمليات؛ يبقى مدخلاً للنظام نفسه.

## المسار المقترح

تبسيط الشاشات الموجودة والإبقاء على روابطها وواجهاتها البرمجية. إنشاء لوحة نقل موازية يكرر المداخل، وحذف وظائف التسوية أو الموافقة يغيّر قواعد مالية مطلوبة؛ لذلك يُقترح إبقاؤها متاحة مع إظهار العمل اليومي أولاً.

### النقل داخل الحجز

تظهر البيانات الأساسية بوضوح: الحجز، السائق، المركبة، من وإلى، موعد النقل والأجرة، ثم الحفظ والطباعة القائمان. تبقى الرحلات المتعددة والأجرة المستقلة أو الكلية ظاهرتين حسب البيانات الحالية. توضع الحقول الثانوية وفترة إشغال المورد في «تفاصيل متقدمة» مع مؤشر عند وجود إعدادات محفوظة؛ إغلاقها لا يمسح قيمها ولا يغيّر نطاق الحجز الزمني. لا تتغير طريقة احتساب الأجرة تلقائياً عند فتح الشاشة.

### حساب السيارة

تبقى الرحلات والمصاريف والشراكة مداخل واضحة. تُعرض الإيرادات والمصاريف والصافي من نتائج الخادم الحالية وبنطاق الفترة الصحيح. البيانات غير المكتملة تظهر بصفتها غير مكتملة، دون تحويلها إلى صفر. تبقى أجرة العميل وأجرة السائق ومصروف السيارة مبالغ مستقلة.

### الشراكة

يُقدّم العرض اليومي مستحقات كل شريك المعتمدة، المدفوع، المتبقي والمبالغ المعلقة، مع زر «طلب صرف حصة». الإغلاق الشهري له إجراء واضح يعيد استخدام النموذج والتأكيدات الحالية. الاتفاقيات، تغيير النسب، السلف والتسويات التاريخية وسياسة الاحتياطي والإهلاك والتقارير تبقى قابلة للوصول تحت «تفاصيل متقدمة» أو الإعدادات. مستحقات جميع الفترات لا تُعرض كأنها نتيجة الفترة المرشحة.

## الحدود المحمية

- لا تغيير في قواعد الإيراد أو نسب الشراكة أو الخسائر أو الدفعات أو الأرصدة أو الموافقات أو الصندوق.
- لا إنشاء جداول أو ترحيلات أو واجهات برمجية جديدة لهذا التبسيط.
- لا تغيير بيانات الإنتاج ولا سجلات الرحلات أو التاريخ المالي.
- لا تغيير صلاحيات مشاهدة المبالغ أو تنفيذ الإجراءات.
- لا إلغاء لتأكيدات تغيير الأجرة أو متطلبات اعتماد الإغلاق.
- لا تغيير لمسارات الروابط العميقة أو معرّفات العمليات أو حماية إعادة المحاولة.
- لا commit ولا push ولا deploy في هذه المهمة دون طلب لاحق صريح.

## التحقق بعد التنفيذ

فحص عربي RTL على الكمبيوتر والهاتف، وإمكانية الوصول باللوحة، وفتح التفاصيل المتقدمة والروابط القديمة، والمحافظة على قيم الرحلات والأجرة عند الطي والتنقل، وعدم الخلط بين أجرة العميل والسائق. تُفحص حالة الأجرة المستقلة والكلية، الرحلات المتعددة، البيانات الناقصة والأخطاء، المستحق المعتمد والمعلق، وطلب الصرف بمساره الحالي.

تُنفّذ `pnpm run typecheck` و`pnpm run build` و`pnpm run verify:critical` والاختبارات الملائمة للتعديلات. اختبارات الكتابة في قاعدة منفصلة تُسجّل SKIPPED إن لم تتوفر قاعدة اختبار موثقة؛ لا تُستخدم بيانات الإنتاج للاختبار.
