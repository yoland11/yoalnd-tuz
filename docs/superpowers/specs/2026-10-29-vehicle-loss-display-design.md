# Preserve signed vehicle operating results

The existing vehicle financial API wraps four analytical differences in the shared positive-only `money()` input sanitizer. Consequently both kinds of trip result, the financial summary and vehicle-list cards return zero for losses. The shared currency formatter and existing UI already support signed results. The existing transportation test checks a separately implemented arithmetic model, so it did not catch the actual API defect.

Reuse the original revenue/approved-effective-expense sources, subtraction, number DTOs and formatting. Remove the positive-only wrapper from those four derived result expressions. Do not change the global sanitizer: payment inputs, source amounts, refund caps, approvals and other callers still require its current nonnegative behavior. No new money parser, rounding policy, source recognition, financial formula, mutation, journal, schema or UI redesign is needed. This is the minimum correction to the already requested vehicle profitability/loss behavior.

Caller audit: `/admin/enterprise/vehicles/:id/financial` feeds the original `VehicleDetail` summary, trip table and printed statement in `src/views/admin/vehicles.tsx`; the vehicle list's `stats.netProfit` feeds its cards. Other vehicle-endpoint consumers in booking operations, enterprise, koshas and partnership views/reports use vehicle identities, source-specific routes or their own approved partnership results. JSON keys and types remain unchanged; only previously suppressed negative analytical values change.

Tests execute the four actual TypeScript API initializer expressions and actual formatter, not a duplicate subtraction helper. Cover loss/profit/zero, both trip sources, fractional existing revenue, large values and unchanged global input sanitization. Run original transport contracts and mandatory financial/critical verification before release. Database writes/concurrency/save-smoke stay SKIPPED without a separately verified TEST configuration; no Production diagnostic business writes.
