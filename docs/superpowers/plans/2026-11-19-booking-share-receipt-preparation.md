# Booking WhatsApp receipt and preparation attachments

**Goal:** Extend the existing Booking Center details/photos WhatsApp bundle with a real booking-receipt image and the original preparation list. The user explicitly selected Booking Center, not research; no research changes are part of this task.

**Design:** Two visible attachment choices in the same original share dialog. A receipt uses the existing branded A5 `buildBookingReceiptHtml` with the already-authorized canonical booking summary; it requires the financial inclusion switch. Preparation uses the original authorized `/admin/booking-operations/:source/:id/preparation` GET, validates source/ID/items, and exports only allowlisted names, quantities, departments, item codes and separately labelled actual preparation state versus availability. Products/assets/manual checklist entries share one source, never reconstructed from product photos. Split long lists into bounded PNG pages with the existing A5 image renderer. No private notes, internal IDs, stock counts, staff assignments, costs or QR secrets in outbound preparation images.

**Caller scope:** `BookingShareDialog` alone calls `prepareBookingShareCards`; its existing unit tests also call it. Add optional receipt/preparation parameters so omitted options preserve legacy output. New pure adapters/builders are local to sharing. Existing receipt builder, A4 invoice, print actions, finance aggregation, preparation data/writes, permissions, APIs and storage remain unchanged. Source/query/option changes invalidate the whole prepared bundle; attachment errors block it, never silently omit selected documents. Native sharing passes the same real files and text; desktop uses existing preview, copy/download and manually attached WhatsApp sending.
