# تبسيط النقل وحسابات المركبة والشراكة — 2026-11-03

## التسليم

مكتمل ومفحوص محلياً. لم يُنشأ commit ولم يحصل push أو نشر. لم تتغير قاعدة البيانات أو البيانات المالية أو الخوادم أو واجهات API أو قوالب الطباعة.

## الاستخدام

- من تفاصيل الحجز، افتح النقل: المركبة والسائق والمسار والموعد والأجرة ظاهرة مباشرة، ثم الحفظ والطباعة. الحجز القديم قابل للتحرير أيضاً. «تفاصيل متقدمة» تحوي الحقول الثانوية وفترة الإشغال، مع مؤشر عند وجود قيم محفوظة. الطي لا يمسح القيم.
- من `/admin/vehicles` افتح السيارة: تظهر الرحلات افتراضياً، مع المصاريف والشراكة كإجراءات يومية. بيانات السيارة والصيانة وسجل العداد تحت التفاصيل المتقدمة. تبقى الروابط المباشرة مثل `?tab=overview` و`?tab=partnership` صالحة.
- الشراكة النافذة تفتح مستحقات الشركاء. الإعداد غير المكتمل أو الاتفاق المستقبلي يفتح الاتفاق. توجد مداخل واضحة للنشاط والإغلاق الشهري، وللاتفاق والتسويات والكشوف ضمن التفاصيل المتقدمة. معاملات الرابط الأخرى، ومنها `partnershipTab`، تُحفظ عند التنقل.
- تعرض بطاقات الشركاء الاسم والاستحقاق والمدفوع والمتبقي والمعلق والمتاح للطلب مع الإجراء الأصلي. طلب الصرف يبقى خاضعاً للموافقة. مرشح النشاط لا يُعرض كأنه يغير مستحقات جميع الفترات.

الفحوص الفاشلة قبل الإصلاح أثبتت السلوك الجديد للتنقل والتفاصيل المختصرة وعرض البطاقات. فحص متصفح للإغلاق الشهري أثبت أن الحقول المطلوبة المخفية كانت تمنع الإرسال دون إظهارها؛ الآن تُفتح تفاصيل السياسات عند التحقق غير الصالح مع الاحتفاظ بالتحقق الأصلي.

اختُبر حفظ أجور رحلتين مستقلتين، تأكيد تغيير طريقة الأجرة، حفظ الحقول الثانوية وفترة الإشغال بعد الطي، إعادة المحاولة بعد التعارض بنفس البيانات، هوية الرحلة في الطباعة، وضع القراءة فقط وأخطاء القراءة. واختُبر فشل تحديث حساب السيارة مع بيانات مخزنة: يبقى نموذج الصرف ومحاولته المثبتة مفتوحين، وإعادة الإرسال تستخدم جسم الطلب والمرجع نفسيهما. فشل القراءة الأولية يُعرض كخطأ مع إعادة المحاولة.
