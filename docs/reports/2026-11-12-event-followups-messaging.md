# متابعة المناسبات والإرسال الجماعي — AJN

حالة الإصدار: اكتمل التنفيذ والفحص في مساحة `event-followups`، ثم طلب المالك الرفع والنشر بتاريخ 2026-11-12. طُبّق الترحيل الإضافي 0138 على Production عبر اتصال DATABASE_URL المالك، وتحققت ثلاثة أعمدة وستة جداول وعشرة مفاتيح خارجية وصحة المؤشرات. لا حذف أو إعادة كتابة لسجلات تاريخية، ولا إرسال رسائل حقيقية أثناء الإصدار.

## ما أُضيف

- توسيع مركز المتابعة الموجود، مع الحفاظ على رابط `/admin/customer-followups` وربط بوابة الموظف وصلاحيات الإسناد القديمة.
- ست بطاقات، بحث وجدول/بطاقات للموبايل، تاريخ مناسبة متوقع، حالات تواصل تفصيلية، ملف العميل وحجوزاته وسجل المتابعات والملاحظات.
- إنشاء متابعتي الحنة والزفاف تلقائياً عند حجز الخطوبة من مسار Booking Center ومسار حجز الكوشة الأصلي، داخل معاملتهما، بلا تكرار. مراجعة يومية محدودة للمصادر الحديثة والتذكيرات، دون تعديل الحجوزات التاريخية.
- الاحتفاظ بمسار التحويل الأصلي للحجز، وهوية العميل، والتحقق من الحجز المرتبط. لا يُنسب أي حجز مستقل إلى متابعة بمجرد تشابه الهاتف؛ الربط يبقى عبر إجراء المتابعة الأصلي أو رابط الحجز المؤهل.
- اختيار العملاء وممثلي مجموعات التخرج وطلبات التخرج؛ بحث ومرشحات للمتبقي والمناسبات القادمة والطلبات غير المكتملة. معلومات المجموعات مجمعة لممثلها الأصلي فقط، وبيانات الطلب الفردي تخص صاحبه فقط. لا تُرسل أسماء الطلاب الآخرين أو القياسات أو الملاحظات الداخلية أو رموز الانضمام.
- ثمانية قوالب محلية، ومعاينة فعلية لكل مستلم، قائمة مستلمين، عدد الأرقام الفريدة، المصدر والخدمات والمبالغ والحالة والموعد.
- حفظ حملة غير قابلة لتغيير محتواها بعد الحفظ، ثم موافقة المدير. تغيّر المصدر بين المعاينة والحفظ يستدعي معاينة جديدة. إعادة قراءة صلاحيات الموظف وإسناد العميل عند الوصول إلى الحملة.
- فتح واتساب يدوياً بعد الموافقة، مع تسجيل «فُتح واتساب يدوياً» فقط. لا يُسجل وصول أو إرسال فعلي من فتح الرابط.
- إرسال رسمي بقوالب Meta المعتمدة فعلياً، مع موافقة موثقة مرتبطة بالطرف ورقمه الحالي، واحترام الإيقاف. العروض تتطلب موافقة أيضاً عند الفتح اليدوي. يُعاد التحقق قبل المعالجة.
- سجل إرسال وموافقة وتسليم، وتوقيع webhook، وصندوق استقبال صغير يحتفظ بحالة التسليم المبكرة حتى وصول رد الإرسال؛ يُنظف بعد سبعة أيام، بينما يبقى سجل الحملة.
- مطالبات إرسال محفوظة ومعاملات وأقفال تمنع الإرسال المتزامن والتكرار خلال 24 ساعة لنفس الرقم والنص. نتيجة المزود غير المؤكدة لا تُعاد تلقائياً.
- خمسة عمّال محدودين لكل حملة، حتى 100 مستلم. الخطأ الدائم يوقف الحملة ويُسجّل السبب، وتستمر بقية الحملات.

## طريقة الاستخدام

1. العملاء ← متابعة المناسبات والإرسال الجماعي.
2. من متابعة المناسبات: افتح العميل، حدّد الموعد المتوقع والحالة والملاحظة؛ استخدم الاتصال/واتساب أو الإكمال/التأجيل أو إنشاء الحجز الأصلي.
3. من الحملات والإرسال الجماعي: اختر المصدر والمستلمين، ثم القالب والطريقة والموعد الاختياري.
4. اضغط «معاينة الرسائل»، وراجع كل مستلم ونصه، ثم «حفظ وإرسال للموافقة».
5. يفتح المدير «المعاينة والسجل» ويراجع الرسائل ثم يعتمد الحملة.
6. اليدوي: يفتح الموظف رسالة كل مستلم ويراجعها ويرسلها بنفسه. الرسمي: تُعالج الحملة بعد حلول موعدها في الدورة الحالية أو بزر المعالجة المخوّل.

## إعادة الاستخدام وحماية الحسابات

أُعيد استخدام `customer_followups` وأحداثه وتفضيلات التواصل، العملاء والموظفين، `service_orders` و`kosha_bookings`، مجموعات وطلبات وتجهيزات التخرج، الإشعارات وإرسال push الحالي، `whatsapp_log` وأسرار Meta الموجودة، و`getBookingFinancialSummary` لقراءة متبقي الحجز.

لم تُعدّل صيغ المدفوع أو المتبقي أو المحاسبة أو الصندوق أو المخزون. لا توجد حركة مالية عند المعاينة أو الموافقة على حملة أو الطباعة/فتح واتساب. مواعيد التصوير وتسليم التجهيزات منفصلة عن تاريخ الحفل، والمعلومة غير المتاحة تُعرض صراحة.

نطاق الملفات المشتركة: `api.ts` يربط إجراء إنشاء الحجز وإجراء حجز الكوشة الأصليين والتذكير اليومي فقط؛ `customer-followup-route.ts` يضيف أخطاء المزود إلى نفس عقد AJN المنظم؛ بقية المتصلين هم صفحة الإدارة وبوابة الموظف وتذكير الشريط ومسار تحويل المتابعة الأصلي. بقيت الروابط والصلاحيات والعقود القديمة متوافقة.

## قاعدة البيانات والتفعيل

ترحيل إضافي معزول: `lib/db/migrations/0138_event_followup_campaigns.sql`.

يضيف ثلاثة حقول اختيارية للمتابعة وستة سجلات مساندة للحملة والمستلمين والموافقة والأحداث وإشعارات التسليم والتذكيرات. لا يحذف أو يعيد كتابة تاريخ العملاء أو الحسابات. يتضمن التحقق من الأعمدة والمفتاح الفريد. طُبّق وأُعيد تطبيقه على PostgreSQL TEST محلي جديد، ثم طُبّق على Production بعد طلب النشر وتحققت كائناته. التراجع التشغيلي يكون بإيقاف الميزة مع إبقاء السجلات، دون حذف تلقائي للجداول.

قبل تفعيل API في بيئة منشورة يلزم إعداد Meta الحقيقي: `META_WA_PHONE_ID` و`META_WA_TOKEN` الموجودان، و`META_WA_BUSINESS_ID` و`META_WA_GRAPH_VERSION` و`META_WA_APP_SECRET` و`META_WA_WEBHOOK_VERIFY_TOKEN`. لا تُخزن الأسرار في الواجهة. مسار webhook هو `/api/webhooks/whatsapp`.

## حدود واضحة

- الجدولة تستخدم Cron اليومي الموجود؛ لا تدّعي الإرسال في الدقيقة المحددة. حتى ثلاث حملات بكل دورة، وكل حملة حتى 100 رقم فريد؛ يمكن للمدير معالجة حملة مستحقة يدوياً قبل الدورة.
- API يدعم قوالب نصية معتمدة ذات BODY وFOOTER ومتغيرات موضعية. قوالب الوسائط والأزرار تحتاج دعماً منفصلاً، وتُرفض بوضوح حالياً.
- يعرض اختيار العميل بيانات آخر حجز أصلي نشط، وتُظهر المعاينة مرجعه. المرشحات تُطبق على الصفحة المحدودة الحالية؛ التصفح التالي متاح، ولا تُجلب قاعدة العملاء بلا حد.
- نجاح طلب المزود يعني «قبلها واتساب»؛ الوصول والقراءة يتطلبان webhook فعلياً. حالة غير مؤكدة تحتاج مراجعة ولا تُعاد آلياً.
- إعداد حساب Meta الحقيقي والإرسال الحي يحتاجان إعداد المزود والقوالب والموافقات؛ لا يجري إرسال رسائل حقيقية لمجرد رفع الكود أو نشره. أصبح ترحيل Production جزءاً من الإصدار بناءً على طلب المالك اللاحق.

## التحقق

- `pnpm run test:event-messaging`: اختبارات القوالب، توقيع webhook، الحمولة الرسمية، timeout غير المؤكد وأخطاء الإعداد.
- `pnpm run test:event-messaging-db`: PostgreSQL معزول، الإسقاطات الحقيقية، الموافقة، المعاينة القديمة، إعادة المحاولة، إيقاف التواصل وتغيير الممثل، الخصوصية، التزامن، التسليم المبكر، سحب الإسناد والموافقة، وحملة 12 مستلماً بعد حملة ذات معتمد معطل.
- `pnpm run test:customer-followups`: اختبارات المركز الأصلي وتحويل الحجز والهوية والصلاحيات.
- اختبارات المتصفح الحالية والجديدة عند 1440 و390 بكسل، مع لقطات الشاشة، دون أخطاء صفحة أو تجاوز أفقي.
- `pnpm run verify:critical`: **PASS** على النسخة النهائية. شمل TypeScript والبناء واختبارات الدفع والأنظمة الأخرى و`test:save-smoke` على PostgreSQL TEST مستقل، ولم تكن اختبارات الحفظ متجاوزة أو معروضة كنجاح وهمي.
- الترحيل 0138 وفحوص كتالوج قاعدة البيانات: **PASS**، بما في ذلك إعادة التطبيق الآمنة.
- المراجعة المستقلة: أصلحت الملاحظات الست المتعلقة بسحب الموافقة والإسناد، تعطيل حملة لا يوقف البقية، التسليم المبكر، حملة بأكثر من عشرة مستلمين، وموعد تصوير العميل. المراجعة المحدودة الثانية أكدت الحلول دون ملاحظات مهمة متبقية.
- لا يوجد أمر lint عام في package.json؛ استخدم Prettier للملفات الجديدة وفحص Git للمسافات.
